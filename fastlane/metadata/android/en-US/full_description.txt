KeepADB helps keep Android Wireless Debugging available across device restarts, Wi-Fi reconnects, access-point changes, and idle periods.

Toggle Wireless Debugging from the main screen, a Quick Settings tile, or a home-screen widget. An optional foreground service monitors the connection and attempts recovery when Android disables it. Android may ask for approval to enable Wireless Debugging on Wi-Fi. Approve only expected prompts on a private network you trust. Select “Always allow on this network” if you want Android to allow Wireless Debugging automatically when your device reconnects to that network. KeepADB cannot grant this Android approval itself; its trusted-network rule is separate and only controls where automatic recovery may run. If Android does not confirm an automatic enable, KeepADB backs off instead of retrying rapidly.

Features:
* Quick Settings tile and main app controls
* Two home-screen widgets: KeepADB controls grows with its size (Wireless Debugging, Keep-Alive, webhook auto-sync; main action and order per widget), KeepADB overview shows address, Wi-Fi, Keep-Alive and webhook delivery at a glance
* Optional Keep-Alive service across restarts and network changes
* Endpoint discovery through Android NSD/mDNS (_adb-tls-connect._tcp); timing depends on network conditions
* Optional HTTP(S) webhook, disabled by default, for verified Wifi-ADB endpoints
* Configurable status notification and endpoint display
* Three optional privacy switches that hide names and addresses in the app, in notifications, and in widgets and the tile
* Networks list to trust, block, and name Wi-Fi access points; optional Force mode, for a chosen time or until you end it
* 19 interface languages and right-to-left layout support
* No advertising, analytics, tracking, or third-party runtime libraries

On fresh installs, Keep-Alive re-enables Wireless Debugging automatically only at access points you have trusted; existing installations keep their previous network setting. Recognizing trusted networks requires precise Android location access. KeepADB's Keep-Alive service is set up so that identity stays readable in the background too, as long as it was started while the app was open; recovery can still pause if the permission is missing or approximate, or location is off. A service instance that has only ever been started in the background (e.g. after a restart or an app update) keeps the identity masked until the app is opened again, unless you also grant Location "Allow all the time" on KeepADB's Android permission page — an optional step offered as a closable card on the main screen while trusted networks are required. KeepADB cannot grant this for you and, as with all location access here, only uses it to identify the Wi-Fi network; it does not read or store your location.

When USB debugging is connected, KeepADB can show a USB notification and associate it with an editable host profile stored on the device. It can optionally offer or perform a USB-to-Wifi-ADB handover. USB profile data is not sent through the current webhook contract.

KeepADB does not require root. Android protects Wireless Debugging with the WRITE_SECURE_SETTINGS permission, so initial setup requires granting it once from a trusted computer with ADB:

adb shell pm grant de.hohnepeople.keepadb android.permission.WRITE_SECURE_SETTINGS

Wireless Debugging exposes an authenticated development service on the connected network. Use Keep-Alive on networks you trust, turn Wireless Debugging off on public hotspots, and reject unexpected Android approval or pairing prompts.
